## 一键启动（本地界面 / 服务）

日常使用**只需要双击 `启动.bat`**，它会起一个进程、自动打开浏览器：

| 用法 | 做什么 |
|---|---|
| `启动.bat` | 生产模式：单窗口运行，服务就跑在这个窗口里，**Ctrl+C 或关窗口即停** |
| `启动.bat dev` | 开发模式：API + Vite 两个窗口，前端改代码热更新 |
| `启动.bat rebuild` | 先强制重建前端产物，再按生产模式启动 |
| `启动.bat setup` | 装/更新依赖（后端 pip + 前端 npm） |
| `启动.bat check` | 只体检并打印报告，**不启动也不停止任何进程** |

可选开关：`-Port 8001` 换端口 · `-NoBrowser` 不自动开浏览器 · `-NoRestart` 发现旧进程也不重启 ·
`-SkipBuild` 前端产物过期也不自动重建。

它会自动处理三件容易浪费时间的事：

1. **前端产物比源码旧 → 自动重建**（改了 `web/src` 不用记得跑 `npm run build`）；
2. **端口上跑的是旧代码 → 自动停掉重启**。判据是 `/api/health` 里 `code.backend_stale`
   —— 它比的是「进程启动那一刻的源码 mtime」与「磁盘当前 mtime」，
   不是两个进程各自读到的磁盘现值（那样永远相等、比不出来，第一版就错在这里）；
3. **依赖没装 → 明确提示跑 `启动.bat setup`**，而不是挂在 import 阶段装作"代码坏了"。

> ⚠️ 这些脚本为什么分成 `.bat` + `.ps1` 两层：`cmd` 按**当前代码页**逐字节读 `.bat`，
> 文件里的 UTF-8 中文会被当成 GBK、字节错位后把命令切碎（`timeout` 变 `meout`、
> `if not exist` 变 `exist`），报一堆"不是内部或外部命令"；而 **LF 换行**也会让
> cmd 的解析错位（同一个脚本实测：CRLF 版 8/8 步全部正确，LF 版只剩 4 步且命令被切碎）。
> 所以根目录的 `启动.bat` 是**纯 ASCII + CRLF**，只负责转发参数给
> `scripts/launch.ps1`（UTF-8 **带 BOM**，中文在这里打印，走 Unicode 控制台与代码页无关）。
> 改动 `启动.bat` 时请保持这两个约束。

研究与实盘共用，杜绝"回测里有效、上线后算出另一个值"。

| 组 | 因子 |
|---|---|
| 动量 | `mom_20` `mom_60` `mom_120` `mom_60_vol_adj` |
| 反转 | `rev_5` |
| 风险 | `vol_20` `vol_60` `dvol_20` `mdd_20` `skew_20` `hl_range_20` |
| 趋势 | `ma_bias_20` `ma_bias_60` `ma_cross_5_20` `rsi_14` `stoch_pos_20` |
| 量能 | `vol_ratio` `turnover_chg` `amihud_20` `amount_log_20` `up_down_vol_20` `vol_price_corr_20` `turn_rate_20` |
| 结构 | `days_since_high_60` `limit_up_cnt_20` `gap` `intraday_ret` |

| 估值 | `bp` `ep` `sp` |

> **方向表是实测校准过的，不是教科书抄来的。** 初版照搬美股经典因子库，实测发现
> **27 个里有 13 个在 A 股是反的**（按错误方向打分时，"策略最想买的前 20%"年化仅
> 10.95%，而"最想避的后 20%"年化 16.52%——即在系统性反向选股）。方向已按
> **中性化后的逐日横截面 RankIC 符号**修正，一致性 27/27。
> 定方向的方法论坑（不要用分组平均收益、不要用 RAW 数据）写在 `vlib.py` 的注释里。

工具链：

| 模块 | 作用 |
|---|---|
| `aq/factors/vlib.py` | 向量化因子内核（**唯一权威实现**）+ 先验方向 |
| `aq/factors/panel.py` | 因子面板：全市场流式构建 + 前瞻收益对齐 + 可交易标记 |
| `aq/factors/neutralize.py` | 行业 + 市值中性化（FWL 定理全表向量化） |
| `aq/factors/ic.py` | 自研 IC 检验：IC / RankIC / ICIR / **Newey-West t** / 分位收益 / 衰减 / 换手 |
| `aq/factors/walkforward.py` | 滚动窗口 walk-forward 选参（避免用未来数据挑参数） |
| `aq/backtest/cscv.py` | **CSCV / PBO / Deflated Sharpe** —— 防过拟合三件套 |
| `scripts/factor_research.py` | 一键：建面板 → 中性化 → 逐因子检验 → 去冗余 → 出报告 |
| `scripts/cscv_test.py` | 一键：多配置回测 → CSCV 过拟合概率 → 分年度拆解 |

两个容易踩的坑，代码里已处理：

1. **一字板不可交易**：次日停牌 / 一字涨停（买不进）/ 一字跌停（卖不出）都打上
   `t1_tradable=False`，IC 检验自动剔除，否则会算出"买一字板"的假 alpha。
2. **重叠持有期的高估**：持有 5 天时，相邻两天的 IC 样本高度重叠，IC 序列自相关，
   普通 t 检验会系统性高估显著性。因此 t 值默认做 **Newey-West 修正**。

打分权重支持两种来源（`config/*.yaml` 的 `model.weight_source`）：
`prior`（内置先验）或 `ic`（读最近一次因子研究的 RankICIR 自动定权，
符号直接取实测 IC 方向）。找不到 IC 结果时静默降级为先验，不会让线上流程崩掉。

`model.factor_include` 可指定**因子子集**（如 `["bp","ep","sp"]`）跑单组实验。
⚠️ 必须走这个配置项、不能只筛 `summary.csv` —— 打分器的 min-max 归一化会把子集里
最弱的因子恒压成 0 分且永不复权，直接导致"某因子无效"的伪结论。

`model.score_neutralize`（默认 `true`）控制打分前是否做**行业 + 市值中性化**。
必须与 IC 估计口径一致，否则回测的 alpha 是口径错位造出来的——理由与实测数据见
[研究结论第 4 条](#4-已修复的两处口径-bug)。
置 `false` 只用于 A/B 复盘对照，**不要用它下结论**。

## 研究结论（重要）

**口径**：股票池 `universe.index = all` + 上市满 180 天 + 近 20 日日均成交额 ≥ 2e7（下称 liquid 池）；
起点 2019-01-01（跨越 2019 牛、2020 疫情、2021 抱团、2022 熊、2023–24 震荡、2025–26 反弹）；
全样本 31 因子。**不使用沪深300 成分池做结论**——它含幸存者偏差。

### 1. 量价因子 + IC 加权：无优势

CSCV v2（31 因子 / liquid / 2019 起）——**raw 口径 vs 中性化口径**两轮对照：

| 指标 | raw（旧，`liquid_v2`） | 中性化（`liquid_neu_main`） |
|---|---|---|
| PBO (S=16) | 0.121 | 0.170 |
| 最优配置 t | 0.128 | **0.993** |
| DSR (N=6) | 0.120 | 0.377 |
| 平均 alpha | −0.085 | **−0.010** |
| 配置间 ρ̄ / N_eff | 0.98 / 1.0 | 0.837 / 1.16 |

两轮都不是显著正收益（t ≈ 1 仍远低于显著门槛，DSR 0.38 同样不显著），但**修口径后
整条曲线明显上移**：6 个配置里 4 个正夏普（旧口径只有 1 个），
最优从 `h20d` 的 SR 0.358 / alpha +0.036 / IR +0.051 拿到。

> 📌 **一个值得注意的形状**：按换手从高到低排，夏普是**单调的**——
> `h1d` SR −0.237 < `h5d` 0.054 < `h10d` 0.268 < `h20d` 0.358。
> 换手最高的 `h1d` 也正是拒单最多的配置（8508 笔，其中 6379 笔是"超总仓位上限"、
> 1821 笔是行业 30% 上限被顶穿，且高度集中在计算机/电子 1024 笔），表现最差。
> 这与「交易成本是瓶颈」一致，也是后续 B1（成本感知定权）的立项依据。

分年度 **4 赚 4 亏**（2019 +21%、2020 −18%、2022 −27%、2024 +36%）→ 严重 regime 依赖，
不是稳定 alpha。

### 2. 估值因子独立上场：旧结论「亏钱」是坏口径造的，但也没被救活

先前结论（`cscv_liquid_val_only`，**raw 口径**）：6/6 配置亏损、**最优 t = −0.211**、DSR 0.065。
这个结论**已作废**——它和 IC 的估计口径不一致（口径在中性化上估、组合按 raw 排序）。

修好口径后重跑（`--factor-set valuation`，bp/ep/sp 单因子集，liquid，2019 起，6 配置，扣 rf 2%）：

| 口径 | 结果 | 最优配置 | PBO(S=16) | DSR(N=6) | 最优 t | 平均 alpha |
|---|---|---|---|---|---|---|
| raw（旧·错） | **6/6 全负** | `wic_h10d_t0` SR −0.076 | 0.605（疑似过拟合） | 0.065 | −0.211 | −0.048 |
| **中性化（修好后）** | **5 正 1 负** | `neu_wic_h5d_t0` SR **0.172** / 年化 +3.52% | 0.268 | 0.205 | **0.477** | −0.017 |

- **修口径确实消灭了"深度价值行业押注"**：raw 下低 PB ＝ 全市场最便宜 ＝ 土木工程/黑色金属/房地产，
  30% 行业上限被反复顶穿（单配置最多 **5129 次**），实际暴露只有 70~80%；
  中性化后低 PB ＝ **同行业内相对便宜**，拒单掉到**个位数**，暴露回到 87~94%。
- **但结论只能是「证据不足」**：最优 t = 0.477，连"显著不为 0"都够不上。
- 更关键：**alpha ≈ 0（−0.001）、beta 0.71** —— 那个 +3.52% 几乎全是 beta 换来的。
  扣掉基准看超额口径：**年化超额夏普 −0.150、t = −0.408、DSR 0.044**
  （修正 4.2 的"双扣 rf"后；旧值 −0.287 / −0.778 是同一处 bug 造的，结论方向不变）。

**正确表述**：「估值单因子路线：**无证据支持存在 alpha**」。既不能说能赚，也不该再说它死了。

### 3. 因子层面：IC 显著 ≠ 能赚钱

| 因子 | RankIC | ICIR | t | 换手 | 多空年化 | q_mono |
|---|---|---|---|---|---|---|
| `bp` | +0.0179 | 0.198 | +8.07 | 0.021 | **+6.4%** | 0.842 |
| `ep` | +0.0120 | 0.171 | +6.73 | 0.019 | **−2.8%** | **−0.018** |
| `sp` | +0.0108 | 0.158 | +6.53 | 0.015 | +4.2% | 0.842 |
| `ln_mktcap` | −0.0054 | −0.036 | −1.43 | 0.019 | −13.2% | −0.818 |
| `gap`（对照） | +0.0206 | +0.402 | +18.0 | **0.795** | +82.6% | +0.98 |

- **`ep` 是"IC 显著但价差不可交易"的教科书案例**（q_mono −0.018：分组收益根本不单调）。
- 估值因子的决定性优势是**换手极低**（0.015~0.021，量价因子的 1/30~1/50），正打在
  "交易成本吃掉 alpha"这个瓶颈上；但**幅度太小**（|IC| 仅量价的 1/3~1/4）。
- IC 加权按 |ICIR| 定权、**不看换手** → 估值三因子在全因子组合里只拿到 **4.5%** 权重。

### 4. 已修复的两处口径 bug

#### 4.1 打分口径 ≠ IC 估计口径

**曾经的缺口**：`neutralize()` 只被 `scripts/factor_research.py`（算 IC）调用，
而 **`aq/backtest/engine.py` 的打分路径不做中性化**，只做全市场横截面 z-score。
于是 IC 在"行业 + 市值中性化"口径上估、组合却按 **raw** 口径排序 →
低 PB 在全市场口径下 ≈ "买建筑 + 钢铁" → **深度价值行业押注**。

**修法**（`model.score_neutralize`，默认 `true`）：
`_build_factor_panel` 保留 `industry` / `mktcap` 两列，在**已有的** `groupby("date")`
循环里**逐日**调用 `neutralize()`，再把 `_neu` 列按原列名送回打分器。

- 逐日与整表**数值完全一致**（9.2 万行 × 31 因子，逐格最大差 **0.0**，有效格点 2,840,114）。
  逐日走内存恒定，不必为 730 万行整表再复制一份。
  复现：`python scripts/probes/verify_neu_equivalence.py`（只读）。
- 成立前提：`neutralize()` 每一步都按 `date` 分组。**若将来往它里面加跨日期的东西
  （全样本分位、时序平滑），逐日路径会静默跑偏。**

**效果**（2024 起每 10 日采样、66 个交易日、同一套 IC 权重，只换输入因子）：

| 指标 | raw（旧） | 中性化（新） |
|---|---|---|
| 深度价值行业进 Top-20 次数<br>（土木 / 黑色金属 / 券商 / 房地产） | **87** | **21（−76%）** |
| 行业偏离度 TVD | 0.644 | 0.682 |
| 随机抽 20 只基准 TVD | 0.545 | 0.545 |
| **超额行业偏离**（TVD − 基准） | **+0.100** | +0.138 |

> ⚠️ **目标达成了，但暴露了新问题**：中性化**没有减少行业押注总量**，
> 只是把它从「深度价值（土木/钢铁/地产/券商）」换成了**「科技制造」**
> （电子 +6.5%、通用设备 +2.6%、电气机械 +2.4%）。
> 原因：IC 权重被高换手量价因子主导（`vol_ratio` 0.102 / `turnover_chg` 0.083 …），
> 去行业均值后极值天然聚集在**高离散行业**。
> → `risk.industry_max = 0.30` 仍可能频繁拒单，列为下一阶段待处理项。

> 📌 **判据本身也踩过一次坑**：第一版用「组合行业集中度 HHI」当判据，结论**完全反了**
> （HHI 0.113→0.209，看起来"更糟"）。因为 HHI 把「组合相对池子的行业偏离」和
> 「残差在高离散行业的天然聚集」混在一起了。**任何"从大池子里挑少数"的集中度指标，
> 都必须先减掉随机基准**——74~83 个行业里挑 20 只，随机 TVD 就有 0.545：
> 不减基准的话，0.644 与 0.682 根本读不出任何东西。

**端到端确认**（真实回测，liquid 池，2024-01-01 ~ 2024-12-31，242 个交易日）：

| 指标 | raw（旧口径） | 中性化（新口径） |
|---|---|---|
| 总收益 | −20.21% | **−27.62%** |
| alpha / beta | −0.333 / 0.93 | −0.432 / 0.885 |
| Sharpe | −0.585 | −0.999 |
| 平均仓位 / 平均持仓 | 91.0% / 19.62 只 | 88.4% / 18.94 只 |
| **行业超限拒单** | **27 笔** | **380 笔** |
| 　其中最大来源 | 电力热力 18 / 软件 6 / 医药 3 | **计算机通信电子 321** / 电气机械 30 / 软件 23 |

三点结论，都要如实说：

1. **口径确实进入了打分路径** —— 行业拒单的构成完全变了，
   从"电力/软件/医药"搬到"计算机通信电子"，与 Top-20 分析预测的"科技制造"偏移**逐字吻合**。
2. **修口径不会创造 alpha，只会让测量变准。** 新口径下更差（−27.62% vs −20.21%），
   因为旧口径那个"没那么差"的数字本身就是口径错位造出来的假象。
   两者都远差于基准，与 CSCV 得出的"策略层已被证伪"一致。
3. **预测的新风险被证实**：`risk.industry_max = 0.30` 现在是**硬约束**
   （行业拒单 27 → 380 笔），下一阶段必须处理。

#### 4.2 超额口径把无风险利率扣了两次

`scripts/cscv_test.py` 的 `--excess`（"剥掉 beta、只看超额"的那把尺子）里，
主矩阵 `R` 在第 569 行已被换成 `Rn = R − rf_daily`，而超额那一段又写成：

```python
E = R - B        # R 此时已是「策略 − rf」，B 是【原始】基准收益
```

于是实际算的是 `策略 − 基准 − rf`，比字面含义多扣了一份无风险利率（≈2%/年），
**系统性低估超额收益**——而代码同一段的打印恰恰写着"策略日收益 − 基准日收益"。
（`rf` 是共模项，所以配置间**相对**排序不变 → PBO 几乎不动，但年化夏普 / t / DSR 整体下移。）

**修法**：在覆盖前留一份未扣 rf 的 `R_raw`，超额用 `R_raw − B`。

影响（同一批交易，只换算法，**回测与收益序列一字未动**）：

| 结果 | 口径 | 年化超额夏普 | 超额 t | 超额 DSR |
|---|---|---|---|---|
| `liquid_neu_main`（31 因子，penalty=0） | 旧（双扣 rf） | −0.085 | −0.231 | 0.063 |
| 同上 | **修正** | **+0.052** | **+0.142** | 0.123 |
| `liquid_neu_val`（估值路线） | 旧（双扣 rf） | −0.287 | −0.778 | 0.019 |
| 同上 | **修正** | **−0.150** | **−0.408** | 0.044 |

- 两行的**结论都不变**（|t| 都远小于 2 → 仍无证据支持 alpha）。
- 但 `neu_main` 最优配置的超额**符号从负变正** —— 这正说明"名字写着 A、算的是 B"
  这类 bug 不会报错，只会静默地把结论往某个方向推。
- 已用两条独立实现交叉验证：`--only-stats --excess` 的输出与一个不复用该代码路径的
  探针逐位一致（`scripts/probes/probe_excess_rf.py`）。
- 主口径（绝对收益）的 PBO / DSR / t **完全未变**——每次重算都与旧 json 逐字段比对确认。

> ⚠️ 两处 bug 的共同教训：**口径错误从不报错，只会让数字失真。**
> 所以本仓库把"口径"写进缓存 key / label，并对每个结论标注其口径状态（见第 5 节）。

### 6. B1「成本感知定权」A/B 结论：方向对，但不够显著 → **不采信**

**思路**：`scoring.py` 按 `|RankICIR|` 定权、**完全不看换手**，于是权重恰好压在
最贵的因子上 —— 组合加权平均换手 **0.2641**，而换手只有量价因子 1/30 的估值三因子
合计只拿到 **4.54%** 权重。改成 `|RankICIR| / turnover` 后，
加权换手降到 **0.0732（−72%）**、估值权重升到 **36.58%**。

**验收只认 CSCV 之后的三项指标**（`liquid_neu_main` penalty=0 vs `liquid_cost1` penalty=1；
同池 / 同因子集 / 同打分口径，**只差定权指标**）：

| 指标 | penalty=0 | penalty=1 | 怎么读 |
|---|---|---|---|
| PBO (S=16) | 0.170 | **0.541** | ⚠️ **明显变差**（跨 S 一致：S=8/12/16/20 全部上升） |
| 最优配置 t | 0.993 | 1.122 | 改善，但离显著门槛 2 还很远 |
| DSR (N=6) | 0.377 | 0.425 | 改善，离 0.95 还很远 |
| 超额年化夏普 | +0.052 | +0.130 | 改善 |
| 超额 t | +0.142 | +0.353 | 改善，离 2 还很远 |
| ρ̄ / N_eff | 0.837 / 1.16 | **0.908 / 1.08** | 候选集变得更同质 → PBO 的零假设基准被抬高 |

**机制层面 B1 确实按设计生效了**（逐配置 5/6 改善，仓位系统性上升、拒单系统性下降）：

| 配置 | SR | alpha | 仓位 / 拒单 |
|---|---|---|---|
| `h1d_t0` | −0.237 → **+0.405** | −0.085 → +0.042 | 0.912 → 0.934 / 8508 → 2495 |
| `h5d_t0` | +0.054 → +0.332 | −0.023 → +0.030 | 0.875 → 0.904 / 661 → 458 |
| `h10d_t0` | +0.268 → +0.327 | +0.020 → +0.029 | 0.824 → 0.877 / 451 → 253 |
| `h20d_t0` | +0.358 → +0.402 | +0.036 → +0.041 | 0.756 → 0.837 / 268 → 117 |
| `h10d_t2e7` | +0.208 → +0.291 | +0.010 → +0.022 | 0.728 → 0.818 / 1003 → 589 |
| `h10d_t1e8` | −0.205 → −0.265 | −0.019 → −0.027 | 0.322 → 0.427 / 2700 → 2495 |

**但这不足以采信**，三个理由：

1. **没有一项跨过显著门槛**：t 1.12、DSR 0.43、超额 t 0.35 —— 全部远远不够。
   B 阶段事先写下的判据是「扣除成本后的净 IR **显著**改善」，这没达到。
2. **PBO 反而恶化到 0.541**，且跨 S 一致。部分原因是 ρ̄ 从 0.837 升到 0.908
   （成本感知把 6 个配置都压向同一个"低换手估值组合"，候选集变同质 → PBO 基准上移），
   但这只解释一部分；`pbo_main` 自身的解读已给出「疑似过拟合：挑出来的参数在样本外经常垫底」。
3. **全样本最优配置换人了，而且是反向换**：penalty=0 的最优是 `h20d_t0`（换手最低档），
   penalty=1 的最优却变成 `h1d_t0` —— 而它在 penalty=0 下是**全场最差**（SR −0.237）。
   一个定权指标的改动就让"最优"的 SR 跳了 0.64。这正是 `liquid_v2` 骗过我们的形状：
   **个别配置很漂亮，全样本不成立。**

**结论**：

> B1 的机制有效、方向与「成本是瓶颈」一致，但**幅度远不足以支撑显著改善**，
> 且过拟合风险显著上升 → **不采信 B1**。
> 「IC 加权 + 参数扫描」这条框架**就此封存**（B 阶段的终止条件达成）。
> **后续路线（2026-09-18 更新）**：原计划的 B2（换尺子）已不必单独做 ——
> 它要回答的"超额从哪来"已被直接回答（见「先说结论」最后一行的 ETF 复制检验）。
> 新路线见 [docs/终局诊断与重启方案.md](docs/终局诊断与重启方案.md)：
> **阶段 A 无偏数据底座**（补退市股历史日线，消幸存者偏差）→
> **阶段 B 红利低波**（零假设＝直接买红利 ETF）→ **阶段 C ETF 轮动**。

> 📌 一个方法论收获：**"用样本内 turnover 定权"本身就是一个新自由度。**
> B1 确实降低了组合换手，同时把候选集压得更同质 → PBO 上升。
> 即「更便宜的组合」与「更容易被挑出来的组合」是两件事，CSCV 恰好能区分它们。

### 两个读数陷阱（自己踩过，写下来）

1. **PBO 低 ≠ 好消息。** 低 PBO 只说明"挑参可复现"，要配 t 一起读。
   且配置间 ρ̄ 高时 PBO 天然偏低——PBO 的零假设基准不是固定的 0.5，随候选集上移。
2. **`cscv_*_returns.csv` 存的是扣 rf 后的超额收益**（`R = Rn`），
   而 json 里 `configs[].total_return` 是**未扣 rf 的原始收益**，两者差 ≈ `年数 × 2%`。
   ⚠️ 别把它和 `--excess` 的"超额口径"混为一谈：后者是 `策略 − 基准`、**两边都不扣 rf**
   （见 4.2）——名字都叫"超额"，减的东西完全不同。

## 设计要点

- **一套代码三种模式**：回测 / 模拟 / 实盘共用同一事件循环与撮合内核，只换 `MarketFeed` 与 `TradingGateway`。
- **风控下沉**：单票/行业/仓位/ST/涨跌停等规则集中在校验层，模拟与实盘共用一份。
- **A 股真实规则**：T+1、涨跌停封板不成交、印花税（仅卖出）、佣金最低 5 元、滑点、100 股/手、不可裸卖空。
- **可解释信号**：`signal.json` 携带评分与因子贡献明细，前端可展示"为什么推荐"。

## ⚠️ 后复权价 vs 真实价（务必先看）

这是本项目最容易踩的坑，直接决定回测结果可不可信：

| 用途 | 用什么 | 说明 |
|---|---|---|
| 因子 / 收益率 / 信号 | **后复权价** `bar.close` | 除权日收益率连续 |
| 撮合 / 资金 / 股数 / 手续费 | **真实价** `bar.open_raw` `bar.close_raw` | 后复权价可能是真实价的十几倍（浦发银行 2026 年：后复权 159.66 元 vs 真实 9.18 元）。用后复权价算资金，能买多少手会全错 |
| 涨跌停判断 | 真实价算完再换算回复权尺度 | 交易所按真实价四舍五入到分；直接在后复权价上乘 1.1 会差约 0.6 元，足以把涨停误判成没涨停 |

`Bar.adj_factor = 后复权价 / 真实价`，是**只在除权日跳变的分段常数**（实测浦发 8 年跳变 9 次、
茅台 13 次，均落在除权日）。数据层同时拉取后复权与不复权两份序列合成它。

**注意**：新浪的后复权价与真实价都只保留 2 位小数，低价股的"分"就是 0.2~0.4% 的量化噪声，
会让 `adj_factor` 每天抖动（170 只股票曾跳变上百次）。因此 `aq/data/adj.py` 会做
**变点检测 + 段内取中位数**，把它还原成真正的分段常数（全市场跳变 83,612 → 20,523）。
已在拉取链路默认启用，历史数据可用 `scripts/fix_adj_factor.py` 就地修复。
